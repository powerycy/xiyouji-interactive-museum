# 西游记 v2 场景链资产方案设计

## 目标

第二七回“三打白骨精”v2 场景链不做“十张人物漫画插图”，而做“十个可点击的剧情证据空间”。主视觉采用 **C 为主，B 为辅**：

- C 为主：物件、剪影、道路、妖气、尸骨、贬书等证据式构图承担剧情推进。
- B 为辅：只在必要场景使用已审核角色图层、背影、局部法器或剪影识别点。

这个方向用于解决第一轮 v2 场景图的问题：生成式整图容易把孙悟空、唐僧、猪八戒、沙僧的脸、服饰、体态和法器画偏。v2 的戏剧张力应来自原著证据、空间推进、光影和点击发现，而不是不可控的生成表情。

## 已确认约束

- 不接运行时 AI 生成。
- 不接真实 360 viewer。
- 不引入拖拽库。
- 不把 rejected drafts 重新接入 seed。
- 10 个 v2 主线 scene node 仍固定存在，顺序沿用 `REVISION_REQUIREMENTS.md`。
- `chapter-027.seed.json` 在合格资源落盘前保持 v1，不写入 `sceneNodes`。
- 通过角色一致性 QA 前，不得把任何 v2 主视觉放进运行时资源目录。

## 视觉语言

v2 场景链的画面应像“原著剧情博物馆展陈”，不是普通漫画分镜。

允许的叙事焦点：

- 白虎岭山路、断路、分岔路、雾中远坡。
- 青砂罐、绿磁瓶、坏掉的饭食、竹杖、老公公包袱。
- 金箍棒剪影、紧箍/头部轮廓、唐僧锡杖、沙僧行李、八戒钉钯轮廓。
- 妖气流向、阴风、骨影、粉骷髅、白骨夫人脊梁字样的非文字化暗示。
- 贬书、纸笔、水磨墨、石头、离队道路。

避免的叙事焦点：

- 依赖生成脸部表情表达剧情。
- 每幕都画清楚人物正脸。
- 让模型自由重画孙悟空、唐僧、猪八戒、沙僧。
- 过度铠甲化、影视化、现代性感化、Q 版化。
- 只有空风景，没有可点击证据。

## 资产生产方式

每个主线场景由以下层级组成：

1. 背景层：白虎岭道路、洞府、山坡、回望空间等。
2. 证据层：器物、尸骨、贬书、法器、妖气、脚印、破碎饭食等。
3. 角色识别层：已审核角色图层、剪影、背影、局部法器或轮廓。只在必要时出现。
4. 交互层：热点坐标、轻量说明浮层、完整展签入口。

如果某一幕确实需要角色存在，优先级为：

1. 使用已审核角色图纸做图层或剪影。
2. 使用背影/局部法器/轮廓。
3. 只在人工确认后使用生成角色全身图。
4. 不使用未经审核的生成正脸表情。

## 10 个主线场景的资产焦点

1. `scene-027-01-baihuling-road`：险山、饥饿、悟空离队。焦点是山路、钵盂/行李、远处无村店的空路。
2. `scene-027-02-demon-motive`：妖气俯瞰取经路。焦点是阴风、远路、白骨洞影，不需要白骨夫人正脸。
3. `scene-027-03-first-disguise`：青砂罐与绿磁瓶。焦点是食器、女子剪影、唐僧方向的道路。
4. `scene-027-04-wukong-returns`：火眼金睛与金箍棒。焦点是金光眼轮廓、棒影、变质食物，不依赖悟空正脸。
5. `scene-027-05-bajie-instigation`：证据被扭转。焦点是坏饭食、八戒钉钯/身影、唐僧锡杖旁的摇摆构图。
6. `scene-027-06-second-disguise`：竹杖与哭声。焦点是竹杖、老妇背影、山坡哭声路径。
7. `scene-027-07-third-disguise`：老公公寻亲。焦点是老公公背影、包袱、骨影与收紧的山路。
8. `scene-027-08-skeleton-reveal`：粉骷髅现形。焦点是尸骨、妖气散开、金箍棒影和唐僧方向的惊惧空间。
9. `scene-027-09-banish-wukong`：贬书与离队路。焦点是纸笔、贬书、分路、悟空背影/棒影、沙僧行李。
10. `scene-027-10-chapter-review`：证据回望。焦点是三次伪装证据、粉骷髅、贬书、白虎岭路径组成的博物馆式总结画面。

## QA 门槛

每张 v2 主视觉进入运行时资源目录前，必须逐张检查：

- 是否有 16:9 主视觉，最低 1600x900。
- 是否不是 rejected drafts、旧单图复制、纯色图或占位图。
- 是否有清晰可点击证据区域。
- 是否符合对应 scene 的原著展签。
- 是否没有不受控正脸表情作为剧情核心。
- 如果出现角色，是否继承已审核角色图纸和 base/state JSON：
  - 孙悟空：猴相、紧箍、行者身份、金箍棒，不重甲武将化。
  - 唐僧：僧人、袈裟、毘卢帽/锡杖、慈悯与误判，不武僧化。
  - 猪八戒：黑胖、长嘴大耳、鬃毛、九齿钉钯，不粉色可爱宠物化。
  - 沙僧：沉稳、蓝靛脸/红发/降妖宝杖或行李识别，不普通光头和尚化。
  - 白骨夫人：伪装、骨相、妖气，不现代性感妖女化。

任何一项失败，该图只能进入 review/rejected 目录，不能写入 seed。

## 数据接入规则

当 10 张图全部通过 QA 后：

- 再创建运行时 v2 scenes 资源目录。
- 再把 `chapter-027.seed.json` 升为 v2 并写入 `sceneNavigation` / `sceneNodes`。
- `sceneNodes[].asset.src` 只能引用通过 QA 的图。
- `sceneNodes[].hotspots` 以证据区域为主，不以人物脸部为主要点击点。
- 旧 `scene` 字段继续保留，供 Studio 对比和回退。

## 页面体验要求

v2 `/chapter/027` 应保持 OpenFlipbook-style image-as-the-UI 体验：

- 点击画面证据先出现 ripple/focus ring。
- 先出现轻量说明浮层，再展开完整博物馆展签。
- next/previous/back/breadcrumb/time scrubber 都使用双图层转场。
- 转场只用 `opacity`、`transform`、`filter`。
- 支持 `prefers-reduced-motion`。
- 移动端底部展签抽屉不得遮断画面转场。

## Studio 要求

`/studio` 在 v2 资源准备阶段必须显示：

- 10 个 scene node 的资源状态：missing、rejected、qa-pending、approved。
- 每张图的 QA 清单。
- 该场景的原著展签、核心线索、热点证据区域。
- 是否存在未审核人物正脸。
- 是否引用 rejected draft。

## 验收标准

- 当前 v1 闭环不受影响。
- rejected drafts 不出现在运行时资源引用中。
- v2 资源没有通过 QA 前，`chapter-027.seed.json` 不写入 `sceneNodes`。
- 新资源通过 QA 后，才允许执行 v2 页面实现计划。
- 浏览器 QA 不只检查最终页，还要截图或录制点击反馈与转场过程。

# 技术规格

## 1. 推荐技术栈

推荐使用：

- Next.js
- React
- TypeScript
- Tailwind CSS 或 CSS Modules
- 本地 JSON 内容文件
- 本地图片、视频、全景资源
- localStorage 或 IndexedDB 保存用户进度

可选库：

- `@dnd-kit/core`：后续可选的小游戏拖拽排序增强，MVP v2 不作为前置依赖
- `Photo Sphere Viewer` 或 `Pannellum`：仅在资源为严格 equirectangular `panorama` 时使用
- `Framer Motion`：章节过渡、徽章点亮、展签动效
- `React Flow`：后续人物关系图或事件图
- `sharp` 或脚本工具：资源尺寸整理

## 2. 应用结构

建议路由：

- `/`：大地图
- `/chapter/027`：三打白骨精章节
- `/chapter/027/game`：章节小游戏
- `/chapter/027/reward`：静态全景预览、360 全景或动画奖励
- `/studio`：本地内容工作台

## 3. 用户端模块

### 大地图

职责：

- 展示取经路线
- 展示章节节点状态
- 支持进入已开放章节
- 展示锁定章节预览
- 展示已获得徽章

### 章节探索

职责：

- 优先加载章节 `sceneNodes`，把章节渲染为全屏视觉场景浏览器
- 若 `sceneNodes` 不存在，才回退到旧 `scene.hotspots` 单图热点模式
- 渲染当前 scene node 的主视觉、可点击热点、前进入口和细节入口
- 打开展签
- 记录展签阅读状态
- 显示探索度
- 在探索度达到 70% 且小游戏所需线索展签都已读完后解锁小游戏入口
- 记录已访问场景、已打开热点、当前场景和浏览栈

### 展签

职责：

- 展示繁体原文
- 展示简体白话解释
- 展示回目和来源位置
- 标记是否已读
- 计入探索度

### 小游戏

职责：

- 使用简体白话
- 使用上移/下移按钮或点击控件调整事件卡顺序；拖拽可作为后续增强
- 选择原文线索卡
- 检查顺序与证据
- 完成后进入奖励

### 奖励与徽章

职责：

- 展示静态全景预览、360 全景或内置动画
- 点亮徽章
- 保存章节完成状态
- 更新大地图节点

## 4. 本地内容工作台

`/studio` 是开发和策展工具，不对最终用户开放，也不需要登录。

MVP 工作台功能：

- 查看章节列表
- 查看三打白骨精章节数据
- 预览主场景图
- 预览热点位置
- 点击热点查看展签
- 查看探索度权重总和
- 查看小游戏事件卡与答案
- 预览章节奖励资源
- 在多个美术资源候选中选择当前使用版本

MVP 可以先只读 JSON，不一定提供写回功能。若要写回，可后续用本地 Node API 或手动导出 JSON 实现。

## 5. 数据存储

内容数据：

- 存放在 `content/chapters/chapter-027.seed.json`
- 下一版在章节 seed 中新增 `sceneNodes` 和 `sceneNavigation`
- `sceneNodes` 存在时作为章节页的权威渲染数据；旧 `scene` 字段保留给 Studio 对比、回退和迁移参考
- 原文来源存放在 `data/raw/xiyouji`
- 视觉资源存放在 `public/assets`

用户进度：

- MVP 使用 localStorage
- 数据包括已读展签、已访问场景、已打开热点、当前场景、浏览栈、小游戏完成状态、徽章状态、已解锁节点

建议 localStorage key：

- `xiyouji.progress.v1`

MVP 版本策略：

- 当前进度结构版本为 `1`
- 读取进度时必须校验 `version`
- 若进度缺失、JSON 解析失败或版本不匹配，重置为干净的 v1 空进度
- `/studio` 或开发调试入口提供“重置本地进度”
- 多章节正式扩展前再补充迁移策略，不在 MVP 内做复杂迁移

## 6. 资源策略

美术资源在开发前生成 MVP 核心包。

开发时必须使用真实资源，不用纯占位图跑完整体验。允许在开发中替换更好的资源，但布局、热点和动效应围绕真实资源设计。

下一版视觉场景链开始前，必须先准备第二七回 v2 场景资产包：10 张独立主线场景图，命名从 `scene-027-01-baihuling-road-v2.png` 到 `scene-027-10-chapter-review-v2.png`。如果资源尚未落盘，应先补齐资源或请求用户提供，不能用同一张白虎岭主图假装多场景。

## 7. 360/动画策略

MVP 预生成静态全景预览、360 图或动画，不做实时生成。当前三打白骨精 v1 资源按静态全景预览展示。

实现上把奖励抽象为资源类型：

```ts
type RewardAsset =
  | { type: "static-panorama-preview"; src: string; thumbnail?: string }
  | { type: "panorama"; src: string; thumbnail?: string }
  | { type: "video"; src: string; poster?: string }
  | { type: "image-sequence"; frames: string[] };
```

当前 `baihuling-360-v1.png` 只按 `static-panorama-preview` 展示，不接 360 viewer。后续如果用户提供合格 360 图或新动画，只需替换章节 JSON 中的奖励资源。

## 8. AI 使用边界

前端用户端不调用大模型，不开放自由问答。

AI 只用于离线生产：

- 展签草稿
- 简体白话解释
- 小游戏卡片
- 美术提示词
- 候选视觉资源

## 9. 测试和验收

至少验证：

- 大地图节点状态正确
- 三打白骨精可进入
- 热点点击位置准确
- 展签打开、关闭、已读状态正常
- 探索度 69%、70%、71% 以及“核心线索展签未读完/已读完”组合下，小游戏入口状态正确
- 小游戏排序和证据匹配能判定
- 奖励资源能播放或展示
- 进度刷新页面后仍存在
- `/studio` 能预览当前章节内容

# 实施计划

> 最新 v2 修改方向以 `docs/review/2026-07-01-mvp-effect-audit/REVISION_REQUIREMENTS.md` 为准。本计划中的基础闭环已完成；下一版应先补齐 v2 场景资产包和 `sceneNodes` 数据契约，再改章节体验。

## v2 章节场景链实施增补

目标是把 `/chapter/027` 从“单张白虎岭主图 + 热点面板”升级为 OpenFlipbook / flipbook.page 式的全屏视觉场景链。OpenFlipbook 只作为 image-as-the-UI 的交互和转场参考；本项目仍使用预设场景资源 + 本地 `sceneNodes` 图谱，不接入运行时 AI 生成、VLM 点击解析、视频流或真实 360 viewer。

### 数据结构和资源前置

1. 固定实现 10 个主线 `sceneNodes`，并新增 `sceneNavigation`，主线顺序以 `docs/review/2026-07-01-mvp-effect-audit/REVISION_REQUIREMENTS.md` 为准。
2. 保留旧 `scene` 字段用于 Studio 对比、回退和迁移；`sceneNodes` 存在时，章节页以 `sceneNodes` 为权威渲染数据。
3. v2 资源必须先补齐 10 张独立主线场景图，建议放入章节 027 的 v2 scenes 运行时资源目录。不能用同一张图、纯色图、低清草图或占位图假装多场景。
4. 10 张场景图还必须通过角色一致性 QA：孙悟空、唐僧、猪八戒、沙僧、白骨夫人的体态、服饰、法器和章节状态必须继承 `public/assets/chapters/027/characters/*-v1.png`、`content/characters/*.base.json` 和 `content/chapters/027/characters/*.state.json`。未通过时不得写入 `sceneNodes`。
5. 如果生成式整图无法稳定保持角色一致性，改用“背景场景 + 已审核角色图层/剪影/局部特写 + 物件/气氛图”的组合方案。
6. 第一轮 v2 场景图已因角色偏离被拒绝，留档于 `docs/review/2026-07-01-v2-scene-rejected-drafts/`，不得作为正式资源引用。
7. 原著展签、繁体原文、简体白话解释继续复用现有 `labels`；探索度只按唯一已读展签权重计算，访问场景、点击热点、打开轻量浮层本身不增加探索度。
8. 进度层可继续使用当前 progress API，并在章节进度中追加 `visitedSceneIds`、`openedHotspotIds`、`currentSceneId`、`sceneStack`、`mainlineUnlockedSceneIds` 等可选字段。页面仍只调用 progress API，不直接读写 storage。

### 页面改造顺序

1. 先完成 v2 场景资源落盘和资源 QA，记录每张图的尺寸、用途、是否重复、是否满足主线叙事和角色一致性。
2. 再定义 `sceneNodes` / `sceneNavigation` 类型、selector 和内容完整性校验。
3. 扩展 progress API，保证旧进度可读，新增场景访问状态不会影响探索度。
4. 将 `/chapter/027` 改为 v2 全屏场景浏览器：默认显示场景图，热点贴合画面，长文展签收进按需打开的浮层或抽屉。
5. 保留小游戏上移/下移排序和证据选择，只升级进入包装和完成反馈。
6. 奖励页继续使用 `static-panorama-preview`，不声称是真 360 viewer。
7. `/studio` 第一版只读预览，但必须能看到场景链、每个 scene 的主视觉资源、热点、关联展签、小游戏数据和奖励资源。

### OpenFlipbook-style 画面转场与交互要求

1. `/chapter/027` 的 v2 场景浏览器使用双图层转场：旧场景图和新场景图叠放。旧图以本次点击坐标为 `transform-origin`，轻微放大、暗化、虚化；新图从同一视觉方向淡入或轻推入，让用户感觉是顺着点击意图进入下一幅画面。
2. 点击人物、物件、道路、妖气、尸骨等热点时，先出现 click ripple / focus ring，再进入轻量说明浮层、完整展签或下一场景。反馈必须发生在画面上，而不是只有按钮状态变化。
3. `next` / `previous` 使用主线方向转场，`back` 使用反向转场，breadcrumb / time scrubber 跳转也必须走转场状态机，不能硬切图片。
4. 当前场景加载时预加载 previous / next 场景图；跳转目标图必须等待图片 `decode()` 成功或确认已可绘制后再揭示，避免白屏、闪烁、跳图。
5. 动画属性限制为 `opacity`、`transform`、`filter`，避免触发布局抖动。建议时长 260-420ms，默认 easing 使用 `cubic-bezier(0.16, 1, 0.3, 1)`。
6. 支持 `prefers-reduced-motion`：关闭大幅位移、缩放和虚化时，仍保留快速淡入淡出，保证状态变化可感知。
7. 移动端同样保留视觉深入感。底部展签抽屉不得打断场景转场，也不得覆盖正在发生点击反馈的画面焦点。

### v2 补充验收标准

1. 从 `scene-027-01-baihuling-road` 连续进入 `scene-027-03-first-disguise`，不出现白屏、闪烁、突兀硬切或布局跳动。
2. 点击热点时有明确的画面反馈，包括 ripple、focus ring、局部视觉聚焦或同等反馈，而不是只有按钮 active/disabled 状态变化。
3. `back` 返回上一层时有反向运动，已读展签、当前探索度、当前场景和浏览栈不丢失。
4. time scrubber / breadcrumb 切换已解锁场景时也保持流畅转场，不直接替换图片。
5. 浏览器 QA 必须录制或截图确认转场过程，不能只检查最终页面状态。
6. 移动端连续切换场景时，底部展签抽屉、轻量浮层和导航控件不遮挡主要点击反馈，不造成布局跳动。
7. 启用 `prefers-reduced-motion` 后，功能路径不变，场景切换仍有快速淡入淡出反馈。

## 关键问题与实际处理

### P0：地图白屏

原因：运行时加载了仓库中不存在的空间 iframe，其白色 404 页面位于地图图像上层。

处理：删除失效 iframe，保留真实地图图像与景深氛围层；默认选中白虎岭并直接显示“进入白虎岭全景”。

### P1：热点可发现性不足

原因：360°首屏没有保证热点位于当前视角，评委可能以为页面只有风景。

处理：新增“原著证据导览 · 11 条”，按 4 幕列出全部展签；点击时同步切换场景、记录进度并打开对应展签。

### P1：WebGL 回退不能完成核心任务

原因：原静态回退只提供“重新载入全景”，无法继续探索。

处理：静态回退复用证据导览与展签，因而仍能读完核心线索、解锁游戏和奖励。

### P1：评委完成游戏成本过高

原因：首次体验要完成 8 张事件卡排序并逐一配证据，不适合 3 分钟评审。

处理：增加明确标注的“加载演示答案”。它只填入正确状态，仍需走正式校验函数后才解锁奖励。

### P1：报名所需公开手册缺失

处理：新增 `/guide`，说明 3 分钟路径、无 Key 行为、WebGL 回退、隐私与内容边界；主导航把内部 Studio 换成使用手册。

### P1：AI 错误与用量边界

处理：无 Key 时返回面向访客的可选功能说明；不再把上游错误细节返回浏览器；问题限制 400 字；增加每来源地址每分钟 8 次的基础限流；补安全响应头。

## 视觉与可用性结论

### 强项

- 米纸、朱砂和水墨全景保持同一视觉系统，地图、展签、游戏和奖励之间连贯。
- 展签在大画面右侧浮层展示，原著行号与三语切换清晰，是最能体现差异点的画面。
- 新证据导览在不遮住大部分全景的前提下，把 4 幕和 11 条证据一次讲清。
- 地图首屏已经直接给出白虎岭入口，评委不需要猜哪些节点可用。

### 无障碍与交互

- 主要按钮、对话框、标签页和导航都有可访问名称。
- 展签支持 Escape 关闭并尝试把焦点还给触发元素。
- 移动端保留触控全景、底部展签与单列手册布局；样式断点覆盖 720px。
- 本次 in-app 浏览器的临时视口覆盖未生效，因此没有把伪造的“手机截图”纳入报名材料；正式公网部署后仍需用真实手机做最后一遍视觉确认。
